Cited names and line ranges check out: AudioOutputService 613 lines (ListenerRegistration :10, registerSystemListener :199, readString :525, readUInt32 :542/:554), StatusPopoverView `case .volume` :152, `PopoverDetail` :271, `detailPanel` :285, MenuBarController constructs the view at :77, AppDelegate 191 lines (store at :58, willTerminate :165), GainEngine start :114 (plan range 118-230 cuts stop() at :220-236, use 114-243), render :264, Controller reconcile :192, CoreAudioHelpers 80 lines, `CA` enum, 6 lproj dirs, DuoBarTests/LocalizationTests.swift. ## 1. Goal
- G1 (high): handoff can double audio or blast full level. `GainEngine.currentExclusions()` (GainEngine.swift:89-112) puts every excluded process into `mirror` (zone 2 hears it unmuted). Plan section "Who taps which app" / T7 excludes outputUID apps from the main tap, so they would also land in the zone-2 mirror tap: zone 2 plays them at raw level plus via SR. Plan must say handoff-excluded apps are NOT added to `mirror`.
- G2 (high): Tascam excludes outputUID apps from its main tap using SR's settings, even when SR is not running. Then the app plays direct to the US-4x4 at 100 %, bypassing master keys. Exclude only while SR is running (SR heartbeat key or NSRunningApplication check for com.jurek.statusring), else leave in main tap.
- G3 (med): handoff switchover order is unspecified. Default switching to US-4x4: if SR drops its engine before Tascam has built the per-app tap, app plays at full level; if SR keeps it, Tascam's main tap hears SR's output PLUS its own per-app tap of the same app (two taps on one process, both mutedWhenTapped: both receive audio, so it is doubled). Specify make-before-break with the `perAppEngineRunning`/applied-set acknowledgement from Tascam (Tascam publishes the bundle IDs it currently taps, SR releases only those), and the reverse on EMBERTON.
- G4 (med): "remembered per app" ok; "dimmed row stays" ok. Per-app output device: stereo mixdown loses >2ch/mono layout, acceptable, note in README.

## 2. Completeness
- C1 (high): `AppAudioStore` public API is not specified, yet T5 (panel) and T6 (popover wiring) run in parallel against it, and T4 depends on `AppAudioService` API (publisher type, `AudioApp` fields are listed but not the callbacks). Add a signature block: `apps: [AudioApp]`, `settings`, `setVolume/setMuted/setOutput/reset(bundleID:)`, `outputs: [AudioDeviceStatus]`, `permission: .unknown/.granted/.denied`.
- C2 (high): store injection path missing. AppDelegate (T4) creates it, MenuBarController.swift:77 (T6 says only "the call site") builds StatusPopoverView; MenuBarController init and its creation in AppDelegate need an extra parameter. Assign both edits to one task.
- C3 (med): permission-denied detection has no method. There is no public TCC query for System Audio Recording; with permission denied tap creation can still succeed and deliver silence while mutedWhenTapped mutes the app (app goes silent). Plan needs: a detector (e.g. input peak stays 0 while app IsRunningOutput for >2 s, or TCCAccessPreflight SPI for kTCCServiceAudioCapture) and a rule that engine stops (unmuting the app) on suspected denial. Also verify `Privacy_AudioCapture` URL on the installed macOS before shipping.
- C4 (med): `--list-audio-apps` (AC1 proof). App is @main SwiftUI (DuoBarApp.swift) with an instance lock (ApplicationInstanceLock acquire); a second launch with a flag exits at the lock if SR runs. Handle the flag before the lock, in `applicationWillFinishLaunching`, and say "quit SR first or flag bypasses lock".
- C5: `defaults write ... appAudio -dict-add com.apple.Music '{volume=0.3;}'` (T4, Proof AC2): -dict-add stores the value as a string, and old-style plist numbers are strings. Decoder must accept string/number/bool coercions or give a PlistBuddy command. Also read from Tascam with `CFPreferencesCopyAppValue(key, "com.jurek.statusring")` instead of `UserDefaults(suiteName:)` (cross-domain, cache).
- C6: no spec for what happens to an engine when a managed app is not running (tap on no process, idle aggregate). State: engine exists only while process objects exist.
- C7: rebuild leak not stated: when an app spawns a new helper process, between helper start and engine rebuild that helper plays untapped at full level (short burst). Document as known limit or rebuild-ahead (create new engine, then destroy old).
- Missing: aggregate input streams. SR's aggregate with the target as main sub-device includes the device's input streams; for AirPods or the MacBook mic this can raise the mic indicator / switch BT to HFP. Copy `setInterfaceInputs(on:false)` (GainEngine.swift:244-262) or the plan's "copy GainEngine.start" must say so.

## 3. Safety
- S1: real-time rules listed correctly (shared UnsafeMutablePointer<Float>). Add: no os_log in the IOProc; peak "ratio" needs per-window max with reset, 0/0 guard (AC2 log), otherwise flaky.
- S2: kill -9 fail-safe (AC8) is right for private taps and aggregates; also applies when SR is merely quit: ensure applicationWillTerminate stops engines (AppDelegate.swift:165 area).
- S3: sleep/wake and device removal rebuild is covered (wake notification), but Bluetooth sample-rate changes need a listener on kAudioDevicePropertyNominalSampleRate of the target; not listed.
- S4: public release: users build locally, in-app updater pulls and rebuilds, so an unsigned/ad-hoc build re-prompts for System Audio Recording on every update; README row should say so. Version 2.1.0 release flags macOS 13 users with an update they can build; gate is fine.
- S5: Tascam's `--nudge` helper skip is correct, but note SR must not tap Tascam's nudge process (bundle same) which plan covers.
